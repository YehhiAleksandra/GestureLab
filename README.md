# GestureLab PC v0.1

Прототип этапа 0 из ТЗ «Переводчик жестов» — та же задача, что у Android-версии, но на ПК: быстрее итерировать и отлаживать, в телефон потом перегоним. Формат JSON-сессий **совместим с GestureLab Android v0.1**: сессии v1 читаются, новые пишутся в v2 (добавлены `kind` и `summary.recorded_frames`), данные с ПК и телефона складываются в одну папку и одну сводку.

## Что делает

- Веб-камера (1280×720) → MediaPipe Hands (2 кисти) + Face Detection.
- Окно с живой статистикой: доля кадров с обеими кистями, доля с лицом, FPS, число рук в кадре. Эталон критерия ТЗ (обе кисти ≥ 90%) на экране.
- Два класса записи: **жест** (клавиша `r`) и **«не жест»** (клавиша `n`) — обычные движения рук, фон для обучения этапа 1.
- Запись сессий: только точки рук (21×3 на кисть, нормированные) + флаги по кадрам. Видео **не сохраняется** (осознанно: приватность и объём).
- Запись валидируется по схеме перед сохранением и идёт атомарно: битый JSON не может появиться в `sessions/`.
- Скелет рук рисуется поверх превью (выключается `--no-preview-landmarks`).

## Установка

```bash
pip install -r requirements.txt        # opencv-python>=4.8, mediapipe==0.10.14
pip install -r requirements-dev.txt    # pytest (только для тестов)
```

**Windows, обязательно:** venv должен лежать в пути **без кириллицы**, например `D:\venvs\gesturelab`. C++-часть MediaPipe открывает файлы графов как ANSI-пути и не находит их в не-ASCII-каталоге (ошибка `hand_landmark_tracking_cpu.binarypb ... does not exist`, хотя файл на месте). Папка проекта при этом может быть любой — важна только папка интерпретатора. При запуске из «кириллического» venv программа печатает предупреждение.

```bash
py -3.11 -m venv D:\venvs\gesturelab
D:\venvs\gesturelab\Scripts\activate
pip install -r requirements.txt
```

`mediapipe` закреплён на `0.10.14`: это последний релиз, где ещё есть legacy `mp.solutions.hands`. Начиная с 0.10.30+ legacy-решения из wheel удалены (mediapipe issue #6192), а переход на Tasks API (`HandLandmarker`) — отдельная задача с изменением формата точек.

## Запуск

```bash
python gesturelab.py                       # камера 0
python gesturelab.py --camera 1            # если несколько камер
python gesturelab.py --input hands.mp4 --no-preview   # offline-прогон видеофайла
```

Клавиши в режиме камеры:

- **r** — старт/стоп записи сессии **жеста** (жест и исполнитель спросит в консоли);
- **n** — то же для сессии **«не жест»** (что делаешь: «телефон», «чешу нос», «поправил волосы»);
- **p** — переключить положение (грудь/шнурок/подставка);
- **q** — выход (идущая сессия сохраняется).

Сессия также закрывается сама: по обрыву камеры, по концу видеофайла и по лимиту `max_session_seconds` (по умолчанию 600 с) — память не растёт бесконечно. За 20% до лимита в консоли печатается предупреждение, чтобы успеть закрыть повторение вручную. Файлы «не жест» получают имя с меткой `ne_zhest_`, чтобы не смешиваться с жестами.

## Конфигурация

`gesturelab.toml` (кладётся рядом с `gesturelab.py`, путь меняется `--config`):

```toml
positions = ["грудь", "шнурок", "подставка"]
fps = 15.0                 # частота записи кадров; 15 — эталон ТЗ
max_session_seconds = 600  # авто-стоп длинной сессии
min_detection_confidence = 0.5
min_tracking_confidence = 0.5
face_confidence = 0.5
```

`--fps 30` перебивает конфиг из командной строки.

## Калибровка

```bash
python gesturelab.py --calibrate sessions/                        # статистика по положениям + рекомендация
python gesturelab.py --calibrate --input hands.mp4 --no-preview    # подбор порога детекции 0.3…0.7 на видео
```

Первый режим считает по уже записанным JSON, какое положение даёт большую долю кадров с обеими кистями. Подобрать `min_detection_confidence` по JSON нельзя — видео не сохраняется, поэтому второй режим гоняет видеофайл на пяти порогах и печатает таблицу.

## Сводка

```bash
python summarize.py sessions/                 # по положениям, с вердиктом >=90%
python summarize.py sessions/ --by-gesture    # разрез по жестам
python summarize.py sessions/ --include-noise # учесть сессии «не жест»
python summarize.py sessions/ --csv report.csv
```

Сессии «не жест» по умолчанию **исключаются**: это фон этапа 1, а не метрика этапа 0. Пропущенные файлы перечисляются в stderr. Сессии с Android (папка `sessions` из `adb pull`) кидай в ту же папку — сводка их подхватит.

## Датасет и baseline-модель (этап 1)

```bash
python export_dataset.py sessions/ --out dataset.npz --window 1.5 --stride 0.75
python train.py dataset.npz --epochs 40 --hidden 32 --save model.npz
python train.py dataset.npz --model model.npz    # проверить сохранённые веса без переобучения
```

`export_dataset.py` приводит кадры к равномерной сетке 15 к/с по `t_ms`, режет окна 1–2 с (вектор кадра — 2 кисти × 63 = 126), метки — жесты, сессии «не жест» не берутся. Сплит train/val — **по исполнителям** (`--val-persons А Б` задаёт вручную; по умолчанию каждый второй): один человек не должен попадать в оба сета, иначе точность завышается. Если исполнитель один, скрипт предупреждает и делит по сессиям.

`train.py` — GRU на чистом numpy (координаты относительно запястья своей кисти), печатает top-1/top-3 на train и val. Это baseline для сравнения положений, не боевая модель; апгрейд-путь — `torch.nn.GRU` с тем же контрактом.

## Формат сессии

```json
{
  "version": 2,
  "kind": "жест",              // или "не жест"; в v1 поля нет — считается жестом
  "gesture": "да",
  "position": "грудь",
  "person": "В",
  "frames": [{"t_ms": 0, "hands": 2, "face": true, "hand_landmarks": [[63 числа], ...]}],
  "summary": {"frames": 300, "recorded_frames": 28, "both_hands_pct": 96.3, "face_pct": 100.0}
}
```

`summary.frames` — сколько кадров **увидела камера** (знаменатель процентов этапа 0), `summary.recorded_frames` — сколько из них **записано** в `frames[]` после fps-гейта. Это разные числа при fps камеры выше целевого; в v1 вместо `recorded_frames` считается `len(frames)`. Любые изменения формата — только с ростом `version` и чтением старых версий.

## Протокол этапа 0 (как в ТЗ)

1. **20 жестов** из словаря v1 (см. `gestures.txt`), **10 повторений** на жест, **2 положения**: «грудь» (камера на груди вперёд, широкоугольная линза) и «шнурок» (камера на шнурке, наклон вверх). Двое исполнителей желательно.
2. Каждое повторение: жест ~1–2 с, пауза ~2 с, сессия 10–20 с. Одна сессия = одно повторение.
3. Камера при записи должна стоять так же, как будет закреплена на теле: прикинь держатель/шнурок, не держи в руке «как удобно».
4. Проверяй отдельно жесты у лица (вопрос, эмоции) — в положении «грудь» они, скорее всего, выпадают из кадра. Если так — в словаре v1 нужны варианты перед телом.
5. Между жестами нажми `n` и 20–30 с поживи обычно (телефон, волосы, нос) — это датасет «не жест» для этапа 1.

Список жестов: `gestures.txt` (31 фраза словаря v1 — можно брать первые 20 или все сразу).

## Как добавить жест

1. Допиши фразу в `gestures.txt` (формат `имя | ситуация`, имя — без пробелов, слова через `_`).
2. Запусти `python gesturelab.py`, клавишей `p` выбери положение, клавишей `r` начни запись и введи имя жеста **точно как в словаре** — оно становится частью имени файла и меткой класса.
3. Сделай 10 повторений (одно повторение = одна сессия), между ними пауза ~2 с.
4. `python summarize.py sessions/ --by-gesture` — проверь, что по этому жесту ≥90% кадров с обеими кистями; если «мимо», поменяй положение или траекторию жеста.
5. `python export_dataset.py sessions/` — новый жест автоматически станет новым классом (метки строятся из имён в папке), затем `python train.py dataset.npz`.

Переименовывать уже записанные сессии не нужно вручную: имя жеста лежит в поле `gesture`, но оно же зашито в имя файла — при переименовании правь оба места одинаково, иначе сводка и датасет разойдутся.

## Известные ограничения

- Legacy `mp.solutions.hands`: на свежих wheel MediaPipe не работает (пин `0.10.14`).
- Кириллица в превью зависит от версии OpenCV: на 4.12 HUD рисует `?????`, на 5.0 — нормально.
- Процент `both_hands_pct` считается по кадрам камеры, а не по записанным — при 30 к/с камере и записи 15 к/с это разные знаменатели (см. формат сессии).
- `train.py` — baseline на numpy: на датасете из десятков окон точность низкая, смысл — зафиксировать метрику и пайплайн.
- В offline-режиме (`--input`) `t_ms` считается по системным часам, а не по таймкоду видео (B25): 6 с видео при скорости обработки ~52 к/с даёт метки до ~2 с. Для метрик этапа 0 не важно, в датасет этапа 1 такие сессии не брать.
