# Этап 8: дообучение на реалистичных потоках и декодер с LM

Дата: 2026-10-25. Ветка `main`, база — коммит `cf15084` (этап 7).
Выбранный маршрут: **A + B** — дообучение CTC на потоках из корпуса глоссов и
улучшение декодера (beam search + LM глоссов).

## 1. Что сделано

**A. Дообучение.** Модель `models/slovo_ctc_corpus.pt` обучена 40 эпох от
`models/slovo_ctc_stream.pt` (этап 7) на смеси 60% потоков из фраз корпуса и 40%
случайных потоков, со SpecAugment и вспомогательной покадровой CE-головой на
изолированных клипах.

**B. Декодер.** Добавлены `sign_beam.py` (префиксный CTC beam search, биграммная LM
глоссов, n-best для lattice) и `tools/eval_decoders.py` (один прогон модели → все
декодеры видят одни и те же логиты). В `tools/dialogue_translator.py` beam-декодер
включён по умолчанию с LM и бонусом за слово.

## 2. Данные и честность протокола

Корпус `Arseniy-Polyakov/parallel_corpus_russian_rsl_glosses`:
- train 2758 фраз, но **уникальных только 675**; test 690 фраз.
- 684 из 690 тестовых фраз **дословно совпадают** с обучающими (B37).
- После проекции на 1000 классов Slovo: 2481 train-фраза покрыта полностью, 616 test-фраз.

Из-за дублей LM, обученная на train, видела почти каждую тестовую цепочку глоссов.
Первый прогон декодера дал на «тесте» 48.9% (LM 0.5) и 87.0% (LM 1.0) — это утечка,
а не качество. Оценка перестроена (B36):
- LM учится на 80% **уникальных** фраз (484),
- 120 уникальных фраз отложены, их записи в LM не входят,
- из отложенных: 60 фраз dev (подбор гиперпараметров), 51 фраза test (финальные числа).
- Потоки строятся из тестовых клипов Slovo — записи не пересекаются с train.

Оценка обучения A использует прежний протокол этапа 7: 200 потоков, seed 1234,
`clean` — 2–6 случайных классов, `with_pauses` — с паузами; плюс новые `corpus` и
`corpus_with_pauses` — 200 потоков из 616 покрытых тестовых фраз.

## 5. Результаты B: декодеры на одних и тех же логитах

Модель `slovo_ctc_corpus.pt`, 200 потоков на набор, seed 1234. LM — 484 уникальные
фразы, dev 60, test 51. Гиперпараметры подобраны по dev: **LM 0.1, бонус за слово 2.0**.

| Декодер | clean gloss | clean edit | corpus gloss | corpus edit | corpus oracle@5 |
| --- | --- | --- | --- | --- | --- |
| greedy | 0.390 | 0.524 | 0.364 | 0.553 | 0.060 |
| beam 8 | 0.389 | 0.525 | 0.371 | 0.548 | 0.060 |
| сглаживание 3 + greedy | 0.008 | 0.918 | 0.006 | 0.929 | 0.000 |
| **beam 8 + LM 0.1 + бонус 2** | **0.425** | 0.528 | **0.409** | **0.532** | **0.170** |

- Beam без LM ≈ greedy: модель уверена, пространство поиска почти не меняет ответ.
- Сглаживание логитов шириной 3 **вредно**: модель выдаёт пики в один кадр
  (max prob ≈ 0.988), усреднение превращает пик в blank. Оставлено как замеренный
  отрицательный результат, по умолчанию выключено (`--smooth 1`).
- LM даёт +4.5 п.п. gloss и −0.021 edit на корпусных фразах; n-best oracle@5 = 0.170
  против 0.060 у greedy — запас для LLM-lattice есть.
- На случайных потоках LM тоже не вредит (+3.5 п.п.): бонус за слово борется с
  пропусками, а вес 0.1 слишком мал, чтобы навязать случайную грамматику.

Подбор по dev (gloss_acc): 0.05/0 — 0.465; 0.1/0 — 0.460; 0.1/2 — **0.523**;
0.2/2 — 0.477; 0.5/6 — 0.455; 1.0/8 — 0.351. Пик устойчив к соседям.

## 6. Найденные баги

**B33 (высокая): тёплый старт терял stride-2 свёртку.** Фильтр копирования
`('inp.', 'conv.', 'enc.', 'pos.')` не включал `down.*` — свёртка прореживания
оставалась случайной. Изолированная проверка дала 1.7% gloss вместо 34.5%.
Добавлен `'down.'`, повторный замер — 34.66% (разница с 34.53% при прямой загрузке —
недетерминизм CUDA). Затрагивало любой `--init` в `tools/train_ctc_slovo.py`.

**B34 (средняя): сглаживание логитов уничтожает предсказания.** См. таблицу:
0.008 gloss. Причина — однокадровые пики. Решение: не сглаживать; ширина 1 по
умолчанию, отрицательный результат зафиксирован.

**B35 (высокая): LM без бонуса за слово схлопывала короткие реплики в пустоту.**
На реальном видео `demo_dialog.mp4` beam+LM вернул `[]`, тогда как greedy —
«почему прийти прийти», «розовый верх». Классический перекос длины: LM штрафует
каждое новое слово. Добавлен `word_bonus` в `ctc_beam_search`; после подбора
(2.0) демо снова даёт непустые глоссы, а корпусный gloss растёт.

**B36 (критическая для выводов): утечка в оценке декодера.** 684 из 690 тестовых
фраз корпуса дословно есть в train. LM на таком тесте запоминает ответ: первый
прогон показал 48.9–87.0%. Оценка перестроена на отложенные уникальные фразы;
честное число — 40.9%. Прежние 48.9/87.0 в отчётах использовать нельзя.

**B37 (данные): корпус почти весь дублируется.** 2758 train-фраз → 675 уникальных;
690 test-фраз. Это ограничивает любую LM по этому корпусу и завышает метрики
при случайном сплите. Для следующего этапа нужен внешний текстовый корпус РЖЯ
или разбиение по уникальным последовательностям (уже сделано в eval).

## 7. Демо на реальном видео

`tools/dialogue_translator.py --video D:\hfdata\demo_dialog.mp4 --no-tts --no-translate`
(343 кадра, 2 реплики):

```
0.0–6.0 с:  почему прийти прийти
7.0–10.4 с: розовый верх
```

Beam+LM+бонус даёт тот же текст, что greedy, но больше не возвращает пустоту.
Это пример «модель уверена»: LM не меняет ответ там, где CTC-пики сильные.

## 8. Что не сделано и почему

- **n-best → lattice в живом переводе не включён.** `nbest_to_lattice` реализован
  и протестирован, oracle@5 = 0.170, но сквозной замер «lattice → LLM → судья»
  не проводился: нужен платный вызов HF router и отдельный протокол. Это
  следующий шаг, а не текущий результат.
- **Нет размеченного непрерывного РЖЯ.** Slovo-тест — изолированные клипы,
  склеенные в потоки. Реальная непрерывная подпись (KRSL, SpreadTheSign) требует
  решения Вадима по лицензии и приватности.
- **LM маленькая** (484 уникальные фразы). Для бытовых фраз этого мало; нужен
  текстовый корпус или LM по глоссам большего датасета.
- **Длинные потоки > 2048 кадров** (≈82 с) не режутся на чанки в офлайн-разборе;
  живой путь ограничен `split_utterances(max_len=15 c)`, поэтому не проявляется.
- **Вспомогательная CE-голова** помогает обучению, но на инференсе не используется;
  отдельного замера вклада aux vs SpecAugment не делалось (обе включены сразу).
