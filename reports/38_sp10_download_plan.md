# План докачки SP-10 для покрытия 191 отсутствующего типа слов

Дата: 2026-11-03. Статус: **требует решения Вадима** (лицензия SpreadTheSign).

## 1. Ситуация

После этапов 35A/B/C выявлен потолок: **55% фраз бенчмарка доходят до оценки**. Причина — 191 тип слов отсутствует в голове модели (3 993 класса). Из них:
- 183 слова встречаются в бенчмарке 1 раз
- 8 слов встречаются 2 раза
- Только 2 слова имеют клипы в tune-сплите (можно добавить без докачки)
- **189 слов требуют новых клипов**

Анализ скачанных видео SP-10 (1 174 ролика): только 1 лемма из 180 отсутствующих есть в скачанном (`побледнеть`). Остальные **179 лемм отсутствуют** — нужна докачка.

## 2. Что нужно сделать

### Шаг 1: Получить полный каталог SpreadTheSign (ru)

**Вариант A** (предпочтительный): API или scraping сайта SpreadTheSign для получения списка всех доступных жестов (слов/фраз) с метаданными:
- Текст жеста (русский)
- URL видео
- Категория/тема

**Вариант B** (если нет доступа): Вадим предоставляет список доступных слов из SpreadTheSign (если у него есть аккаунт/доступ к каталогу).

**Оценка**: ~14K позиций (из контекста проекта).

### Шаг 2: Пересечь каталог с отсутствующими типами

Для каждого из 191 отсутствующего типа:
1. Лемматизировать слово (pymorphy3).
2. Найти в каталоге SpreadTheSign совпадения по лемме или точному тексту.
3. Отметить: найдено / не найдено.

**Ожидаемый результат**: список слов, для которых есть видео в SpreadTheSign.

**Приоритизация**:
- Высокий: слова, встречающиеся в бенчмарке 2 раза (8 слов).
- Средний: слова, встречающиеся 1 раз (183 слова).
- Низкий: слова, не встречающиеся в бенчмарке, но полезные для расширения словаря.

### Шаг 3: Оценить объём докачки

Подсчитать:
- Сколько видео нужно скачать (из найденных на шаге 2).
- Общий размер (из URL можно оценить по аналогии с существующими: ~150-200 KB на видео).
- Время скачивания (при 10 MB/s: ~1-2 мин на 100 видео).

**Ожидаемая оценка**: 100-180 видео × 200 KB = 20-36 MB.

### Шаг 4: Скачать видео

Скрипт (по аналогии с существующим процессом скачивания SP-10):
```python
# tools/download_sp10_additional.py
# Вход: список URL из шага 2
# Выход: D:/hfdata/sp10_rsl/videos/{id}.mp4
# Обновление: D:/hfdata/sp10_rsl/download_state.json
```

**Требования**:
- Не скачивать повторно уже имеющиеся видео (проверка по URL в download_state.json).
- Сохранять метаданные (text, url, size) для каждого видео.
- Логировать ошибки (404, таймауты).

### Шаг 5: Извлечь landmarks

По аналогии с существующим процессом:
```bash
python tools/extract_landmarks.py --videos D:/hfdata/sp10_rsl/videos/ \
  --output D:/hfdata/sp10_rsl/landmarks/ \
  --new-ids <список id новых видео>
```

**Оценка времени**: ~1-2 мин на 100 видео (MediaPipe Holistic на GPU).

### Шаг 6: Обновить инвентарь и сплиты

1. Добавить новые видео в `D:/hfdata/sp10_rsl/sp10_inventory.json` (или создать новый inventory для докачки).
2. Пересчитать сплиты (train/dev/eval) с учётом новых видео:
   - Новые видео идут в **train-сплит** (для обучения).
   - Eval-сплит остаётся прежним (193 клипа) — для честного сравнения.
3. Обновить `D:/hfdata/sp10_tune.json` и `D:/hfdata/sp10_eval.json`.

**Важно**: не менять eval-сплит! Иначе результаты этапов 31-35 станут несравнимы.

### Шаг 7: Расширить голову модели

Новые слова требуют новых классов в голове:
```bash
python tools/expand_ctc_head.py --inventory D:/hfdata/sp10_tune.json \
  --checkpoint D:/hfdata/sp10_expanded/fold0.pt \
  --out D:/hfdata/sp10_expanded_v2/fold0.pt
```

**Ожидаемый результат**: голова с ~4 100-4 200 классов (вместо 3 993).

### Шаг 8: Переобучить модель

На новых данных (train-сплит + докачанные видео):
```bash
python tools/finetune_ctc_phrases.py --inventory D:/hfdata/sp10_tune.json \
  --cache D:/hfdata/sp10_rsl/landmarks \
  --init D:/hfdata/sp10_expanded_v2/init_expanded.pt \
  --work D:/hfdata/sp10_expanded_v2 \
  --epochs 40 --steps 60 --bs 24 --lr 1e-4 --seed 2026 --folds 5
```

**Оценка времени**: ~2-3 часа на GPU (RTX 3060 Ti).

### Шаг 9: Оценить улучшение

1. Запустить `vocab_gap.py` на новой голове — проверить, сколько фраз теперь доходит до оценки.
2. Запустить `meaning_compare.py` на eval-сплите — измерить смысл ≥1.
3. Сравнить с этапом 35B (потолок 55%).

**Ожидаемый результат**: покрытие >55%, смысл ≥1 >8%.

## 3. Риски и ограничения

### Лицензия SpreadTheSign

**Критично**: использование данных SpreadTheSign регулируется их Terms of Service. Из memory: "SpreadTheSign 14K (ToS)" — есть ограничения.

**Требования**:
1. Проверить ToS SpreadTheSign: разрешена ли массовая скачка видео для исследовательских целей.
2. Если ToS запрещает — прекратить работу, искать альтернативу (запись исполнителями).
3. Если ToS разрешает — документировать источник и лицензию в README/отчётах.

**Решение**: за Вадимом.

### Качество данных

- Видео SpreadTheSign — профессиональная съёмка, хорошее качество.
- Но: разные исполнители, разное освещение, разный фон.
- Риск: модель переобучится на специфику SpreadTheSign и будет хуже работать на других исполнителях.

**Митигация**: кросс-валидация на независимых данных (Rutube, запись исполнителями).

### Время и ресурсы

- Шаги 1-5: ~1 день (автоматизировано).
- Шаги 6-8: ~2-3 часа (GPU).
- Шаг 9: ~30 мин (оценка).

**Итого**: ~1-2 дня при наличии доступа к каталогу SpreadTheSign.
