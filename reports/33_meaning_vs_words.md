# Отчёт 33. Смысл против слов: решает ли новый декодер, а не только словарь

Дата: 2026-11-02. Окружение: `D:\venvs\gesturelab`, Python 3.11.9, torch 2.x, CUDA RTX 3060 Ti.
Модель — те же честные фолды (`D:/hfdata/dict_folds_honest`, 3 413 класса), выборка — та же,
что в этапе 32: SP-10 dev+test, 111 фраз после лемменной канонизации.

## 1. Зачем и что входит в этап

Этап 32 замерил новый декодер по словам: замороженный по train кандидат `none/wb4/sm3`
различимо лучше production (+0,099 попаданий на клип, ЦИ [0,045; 0,162]), но платит точностью
(11,6% → 4,9%) и почти перестает молчать (пустых 45% → 0,9%). Пользователь видит не слова, а
перевод, поэтому менять дефолты (B67) по словной метике нельзя — нужен тот же конец цепочки,
который видит глухой человек: глоссы → LLM → судья 0/1/2 + chrF.

Что входит: инструмент сквозного замера с парным бутстрапом, прогон на 111 фразах для двух
конфигов, решение по дефолтам. Что не входит: обучение расширенной головы (следующий этап),
подбор новых параметров декодера (сетку уже перебирали в этапах 31–32).

## 2. Инструмент

`tools/meaning_compare.py` — тот же фолд-протокол, что у свопа (модель фолда не видела свой
held-клип), но дальше n-best цепочки идут в LLM, а судья ставит 0/1/2:

```
python tools/meaning_compare.py --out reports/evidence/meaning_sp10.json
```

Канон по лемме включён по умолчанию (`--no-lemma` возвращает грубую основу), поэтому в
оценку попадают 111 фраз вместо 59.

Первый конфиг в `--decoder` — база сравнения; для каждого последующего считается парный
бутстрап по клипам (4000 ресемплов, seed 2026) по трём метрикам: смысл, chrF, попадание слов.
Пустой top-1 в LLM не отправляется (B50) и засчитывается как 0 по смыслу, иначе судья
дарила бы галлюцинации баллы за пустоту.
