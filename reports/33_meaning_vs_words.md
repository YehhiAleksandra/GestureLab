# Отчёт 33. Смысл против слов: решает ли новый декодер, а не только словарь

Дата: 2026-11-02. Окружение: `D:\venvs\gesturelab`, Python 3.11.9, torch 2.x, CUDA RTX 3060 Ti.
Модель — те же честные фолды (`D:/hfdata/dict_folds_honest`, 3 413 класса), выборка — та же,
что в этапе 32: SP-10 dev+test, 111 фраз после лемменной канонизации.

## 1. Зачем и что входит в этап

Этап 32 замерил новый декодер по словам: замороженный по train кандидат `none/wb4/sm3`
различимо лучше production (+0,099 попаданий на клип, ЦИ [0,045; 0,162]), но платит точностью
(11,6% → 4,9%) и почти перестает молчать (пустых 45% → 0,9%). Пользователь видит не слова, а
перевод, поэтому менять дефолты (B67) по словной метике нельзя — нужен тот же конец цепочки,
который видит глухой человек: глоссы → LLM → судья 0/1/2 + chrF.

Что входит: инструмент сквозного замера с парным бутстрапом, прогон на 111 фразах для двух
конфигов, решение по дефолтам. Что не входит: обучение расширенной головы (следующий этап),
подбор новых параметров декодера (сетку уже перебирали в этапах 31–32).

## 2. Инструмент

`tools/meaning_compare.py` — тот же фолд-протокол, что у свопа (модель фолда не видела свой
held-клип), но дальше n-best цепочки идут в LLM, а судья ставит 0/1/2:

```
python tools/meaning_compare.py --out reports/evidence/meaning_sp10.json
```

Канон по лемме включён по умолчанию (`--no-lemma` возвращает грубую основу), поэтому в
оценку попадают 111 фраз вместо 59.

Первый конфиг в `--decoder` — база сравнения; для каждого последующего считается парный
бутстрап по клипам (4000 ресемплов, seed 2026) по трём метрикам: смысл, chrF, попадание слов.
Пустой top-1 в LLM не отправляется (B50) и засчитывается как 0 по смыслу, иначе судья
дарила бы галлюцинации баллы за пустоту.

## 3. Результат: на переводе кандидат различимо лучше, и это видно по всем трём метрикам

Прогон — 111 фраз SP-10 dev+test, 5 честных фолдов, канон по лемме, 2 287 с, $0,0019
([reports/evidence/meaning_sp10.json](evidence/meaning_sp10.json)). База — production-конфиг
`corpus/0,1/wb2/sm1`, кандидат — замороженный по tune этап 32 `none/0/wb4/sm3`.

| метрика | база (production) | кандидат | парный бутстрап по клипам (4000, seed 2026) |
| --- | --- | --- | --- |
| пустой top-1 | 45,0% (50/111) | 0,9% (1/111) | — |
| перевод выдан | 61/111 | 110/111 | — |
| глосс на клип | 0,62 | 3,50 | — |
| попаданий слов (канон) | 8/352 | 19/352 | +0,099 на клип, ЦИ [0,045; 0,162] — **различимо** |
| смысл ≥1 | 0,9% (1/110) | 6,4% (7/109) | +0,063, ЦИ [0,009; 0,135] — **различимо** |
| смысл =2 | 0,9% | 1,8% | — |
| chrF, среднее | 5,29 | 11,76 | +6,30, ЦИ [4,10; 8,96] — **различимо**, 86 побед против 23 |
| chrF, медиана | 3,17 | 9,21 | — |
| точность глосс | 11,6% | 4,9% | в пользу базы |

По клипам: кандидат берёт смысл 6 фраз, которые база не перевела вовсе или перевела
бессмыслицей, и проигрывает ровно одну.

```
+ «Где?»                 база: пусто                    → нет перевода
                         канд: где                     → «Где?»                      (2)
+ «Радость миру!»        база: больше                   → «Больше, радости больше, восхищаюсь…» (0)
                         канд: радость больше восхищаться больше → «Огромная радость и восторг»  (2)
+ «Простите.»            база: уверенный                → «Это список слов, а не глоссы…» (0)
                         канд: уверенный извиниться уверенный → «Уверенно извиниться.»        (1)
+ «Хорошо!»              база: хорошо                   → «Хорошо лить гордый час скрыть билет…» (0)
                         канд: хорошо лить хорошо       → «Хорошо лить хорошо»         (1)
− «У меня есть вопрос»   база: вопрос есть              → «Есть вопрос.»               (2)
                         канд: мне вопрос тебя вопрос есть помочь есть → «У меня к тебе есть вопрос, помоги мне.» (1)
```

Механика простая: при весе LM 0,1 и бонусе 2 beam на короткой реплике схлопывается в одну
глоссу (0,62 глоссы на клип), а половина клипов — в пустую цепочку. Пустую цепочку переводчик
не отправляет в LLM (B50), поэтому глухой пользователь получает не перевод, а молчание.
Кандидат выдаёт 3,5 глоссы и молчит на одном клипе из 111.

Оговорки, которые надо держать в уме при чтении цифры 6,4%:

- **Это не «работает», а «меньше молчит».** Абсолютно обе величины близки к нулю: узкое место
  не декодер, а словарь головы (этап 32: 31,4% фраз доходит до оценки, потолок 49,9%) и
  и качество распознавания глосс. Разница в декодере не делает перевод полезным — она делает его
  существующим.
- **3 строки из 222 потеряны сетевыми таймаутами** (1 у базы, 2 у кандидата) и засчитаны нулём
  и в судейскую долю, и в бутстрап. Это штрафует кандидата сильнее, потому что ошибок у него
  больше; без этих строк разрыв только растёт.
- **Один независимый набор.** Слова кандидат выиграл различимо на трёх наборах сразу
  (train, dev+test, чужой Rutube-канал — отчёт 32 §6), перевод проверен пока только на
  dev+test SP-10. Кросс-канальный смысл-прогон — следующий.
- Выбор конфига не пересматривался: он был заморожен по канонизированному F1 на tune до этого
  прогона (этап 32), здесь кандидат только подтверждается на конце цепочки.

## 4. Решение по B67: дефолты изменены, одним источником правды

Отчёт 31 оставил смену дефолтов за Вадимом, потому что evidence был словный: «лучше по словам»
не значит «лучше для пользователя». Теперь конец цепочки замерен, и он различимо лучше по
всем трём метрикам, которые видны пользователю (перевод выдан, смысл, chrF). Решение —
перевод боевого декодера на `none/0/wb4/sm3`; откат — одна строка в `TUNED_DECODER`.

Причина, по которой правка не могла быть точечной: пара `lm_weight=0,1 / word_bonus=2,0`
была продублирована руками в трёх местах (B67), и это и был дефект — любой следующий подбор
пришлось бы вносить трижды, с риском разъехаться. Поэтому:

- `tools/dialogue_translator.py` — константа `TUNED_DECODER` (единственный источник), из неё
  берут значения флаги CLI `--decoder/--beam/--lm-weight/--word-bonus/--smooth`;
- `tools/check_translation.py:164` — `Recognizer(model, **{**TUNED_DECODER, 'beam': beam,
  'nbest': nbest})`, конфиг больше не печатается в отчёт вслепую;
- `tools/eval_phrase_clips.py:111` — `Recognizer(str(model), **TUNED_DECODER)`, а в `config`
  выгрузки попадает сам словарь, а не четыре выписанных числа;
- `tests/test_decoder_defaults.py` — зафиксированный конфиг и проверка, что оба места делят
  один объект, а не копию чисел (копия и была B67).

Флаги сохранены: `--lm-weight 0.1 --word-bonus 2.0 --smooth 1` возвращают прежнее поведение
без правки кода.

Что остаётся за владельцем (не трогали): утечка дефолтов `--init`/`--prod` (B62), продвижение
честных фолдов и v4/v5 в точки входа, лицензионное использование SP-10, публичный чекпойнт
11 МБ, пин OpenCV (B2), схема v3.

Неразъяснённые изменения в NoWreck-выводе лежат только в четырёх файлах этапа
(`tools/meaning_compare.py`, `tools/finetune_ctc_phrases.py`, `tools/sweep_decode.py`,

`finetune_ctc_phrases` и `meaning_compare` (раньше по умолчанию считалась грубая основа).
Смысл уехал бы в отчёты только как молчаливое изменение метрики, поэтому сборщик канона
вынесен в один хелпер `build_canon`, а `load_morph` при отсутствии `pymorphy3` не падает, а
печатает «канонизация по основе вместо леммы» и продолжает — дефолт не ломает прогон на
машине без пакета.
