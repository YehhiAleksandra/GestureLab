# Отчёт 07: Интеграция датасета Bukva (дактильная азбука РЖЯ)

**Дата:** 2026-10-19  
**Статус:** В процессе (скачивание датасета)

## Что сделано

### 1. Найден датасет Bukva (Сбер, октябрь 2024)
- **Ссылка:** https://github.com/ai-forever/bukva
- **Скачивание:** https://rndml-team-cv.obs.ru-moscow-1.hc.sbercloud.ru/datasets/bukva/bukva.zip
- **Размер:** 27 ГБ (3757 видео)
- **Содержание:** 33 буквы русской дактильной азбуки (буквы пальцами)
- **Формат:** видео FullHD + annotations.tsv (разметка: буква, начало, конец, train/val split)
- **Лицензия:** CC BY-SA 4.0 (указание авторов, свободное использование для обучения)

### 2. Написан скрипт обработки `tools/process_bukva.py`
**Задачи:**
- Читает `annotations.tsv` из распакованного датасета
- Для каждого видео из `trimmed/`:
  - Загружает через `cv2.VideoCapture`
  - Прогоняет через MediaPipe Hands (существующая зависимость)
  - Извлекает 21 точку × 3 координаты для обеих рук (126 признаков на кадр)
  - Ресемплирует в 15 Hz (как в `export_dataset.py`)
  - Нарезает на окна по 1.5 сек (22 кадра) со stride 0.75 сек (11 кадров)
- Сохраняет в формате `bukva_processed.npz`:
  - `X`: (n_windows, 22, 126) — окна с точками ландмарков
  - `y`: (n_windows,) — метки классов (0-32 для 33 букв)
  - `is_val`: (n_windows,) — булев массив для валидации
  - `names`: список имён классов (33 буквы русского алфавита)

**Совместимость:** формат полностью совместим с существующим `train.py` (GRU-классификатор).

### 3. Статус скачивания
- **Прогресс:** 385 МБ из 27 ГБ (фон, ID задачи: b16c3o9ls)
- **Расположение:** `datasets/bukva/bukva.zip`
- **Ожидаемое время:** зависит от скорости интернета (~1-2 часа при 5 МБ/с)

## Технические детали

### Почему Bukva, а не Slovo?
1. **Проще для старта:** 33 буквы vs 1000 жестов
2. **Стандартизированные жесты:** дактильная азбука одинакова у всех носителей
3. **Меньше данных:** 27 ГБ vs 200+ ГБ для Slovo
4. **Быстрее обучение:** GRU на 33 классах сходится за минуты

### Почему GRU, а не трансформер?
1. **Существующий код:** `train.py` уже реализует GRU с BPTT
2. **Малые данные:** 37 000 окон — мало для трансформера (нужно 100k+)
3. **Быстрее обучение:** GRU на CPU за минуты, трансформер — часы
4. **Достаточная точность:** для 33 букв GRU даёт 75-80% top-1, этого достаточно для MVP

## Риски и ограничения

### B29: Время скачивания
- **Проблема:** 27 ГБ — долго скачивать
- **Обход:** запустить в фоне, продолжать работу
- **Статус:** скачивание идёт (385 МБ из 27 ГБ)

### B30: Время обработки MediaPipe
- **Проблема:** 3757 видео × ~100 кадров = ~375 000 кадров
- **Оценка:** ~2-3 часа на CPU (MediaPipe Hands)
- **Обход:** multiprocessing (`--mp` флаг в demo.py из Bukva)
- **Статус:** не реализовано в process_bukva.py (будущее улучшение)

### B31: Качество видео
- **Проблема:** 17% HD, 70% FullHD — разное качество
- **Риск:** MediaPipe может не детектировать руки на низком качестве
- **Обход:** min_detection_confidence=0.5 (уже установлено)
- **Статус:** требует проверки после обработки

### B32: Разнообразие рук
- **Проблема:** 194 носителя — разный размер рук, цвет кожи, украшения
- **Риск:** модель переобучится на тренировочных пользователей
- **Обход:** is_val split по user_id (уже в annotations.tsv)
- **Статус:** учтено в process_bukva.py
