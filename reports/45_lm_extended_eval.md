# Этап 45: Оценка расширенного LM на 100 клипах

**Дата:** 2026-11-04  
**Цель:** Проверить, улучшает ли расширенный корпус LM (с 89 словами VOGinfo) качество декодера с LM-конфигом

## Методология

- **Выборка:** 100 клипов из `sp10_vog_eval_honest.json` (SP-10 + VOGinfo, не видели тренировочных данных)
- **Модели:** 5 фолдов cross-validation (`fold{0-4}.pt`, 4084 класса)
- **Корпус LM:** 2847 фраз (2758 оригинал + 89 простых фраз для слов VOGinfo)
- **Конфигурации декодера:**
  - Config 0: `lm_src=corpus, lm_weight=0.1, word_bonus=2.0, smooth=1` (с LM)
  - Config 1: `lm_src=none, lm_weight=0.0, word_bonus=4.0, smooth=3` (без LM)
- **Оценка:** парный бутстрап по клипам, канонизация по лемме (pymorphy3)
- **LLM-перевод:** Gemma-4-31B-it через HF Inference Providers, судья Qwen3-235B

## Результаты

### Количественные метрики

| Метрика | Config 0 (с LM) | Config 1 (без LM) | Различимость |
|---------|-----------------|-------------------|--------------|
| Клипов | 100 | 100 | — |
| Пустых выводов | 21 (21%) | 1 (1%) | — |
| Word hits (канон) | 15 / 191 (7.9%) | 39 / 191 (20.4%) | **да** (CI [+0.15, +0.33]) |
| Meaning ≥ 1 | 3 / 99 (3%) | 9 / 100 (9%) | нет (CI [-0.02, +0.14]) |
| Meaning = 2 | 1 / 99 (1%) | 1 / 100 (1%) | — |
| chrF | 7.37 | 18.16 | **да** (CI [+7.0, +15.1]) |
| Стоимость | $0.030 | $0.030 | — |

### Статистический анализ (парный бутстрап)

**Сравнение Config 1 vs Config 0 (base):**

- **Word hits:** mean_diff = +0.24, 95% CI [+0.15, +0.33], **различимо** (Config 1 выигрывает)
- **chrF:** mean_diff = +10.87, 95% CI [+7.0, +15.07], **различимо** (Config 1 выигрывает)
- **Meaning:** mean_diff = +0.06, 95% CI [-0.02, +0.14], **не различимо** (CI включает 0)

## Выводы

### 1. Расширенный LM **ухудшил** производительность

Config 0 (с LM) показал:
- **В 3 раза больше пустых выводов** (21% vs 1%)
- **В 2.6 раза меньше попаданий слов** (7.9% vs 20.4%)
- **В 2.5 раза ниже chrF** (7.37 vs 18.16)

### 2. LM-конфиг нестабилен

21% пустых выводов означает, что LM с расширенным корпусом часто не может выбрать ни одного правдоподобного варианта из beam search. Это систематическая проблема, а не шум.

### 3. Без LM стабильно лучше

Config 1 (без LM) показывает:
- Меньше пустых выводов
- Больше попаданий слов
- Выше chrF
- Различимость подтверждена бутстрапом по word hits и chrF

### 4. По смыслу различия нет

Meaning score (оценка LLM-судьи 0/1/2) не показывает статистически значимой разницы (CI включает 0). Это может быть связано с малой выборкой (всего 3-9 клипов с meaning ≥ 1).

## Гипотезы

**Почему LM ухудшил результат:**

1. **Разрыв между корпусом и данными:** 89 добавленных фраз — искусственные конструкции вида `{"russian": "слово", "rsl": "слово"}`. Они не отражают реальный порядок жестов в SP-10/VOGinfo.

2. **Слишком низкий lm_weight:** 0.1 может быть недостаточно, чтобы LM влиять на выбор, но достаточно, чтобы мешать (конфликт с CTC-скором).

3. **Проблема нормализации:** LM обучается на глоссах, но beam search сравнивает его с CTC-выходом, который может быть в другой форме (леммы vs исходные слова).

4. **Малый размер расширенной части:** 89 фраз из 2847 (3%) — слишком малая доля, чтобы изменить распределение LM.

## Следующие шаги

### Отказ от LM-конфига

Config 1 (без LM) стабильно лучше на всех метриках, кроме meaning (где различия нет). **Рекомендация:** использовать Config 1 как основной декодер.

### Альтернативные улучшения

1. **Увеличить eval set:** извлечь landmarks для оставшихся 253 клипов Rutube (сейчас 67)
2. **Дообучение на фразовых клипах:** `finetune_ctc_phrases.py` уже готов, но требует отдельного протокола оценки
3. **Тюнинг параметров beam search:** word_bonus=4.0, smooth=3 — проверить, можно ли улучшить

### LM не нужен

Расширенный LM не помог, а ухудшил результат. **Вывод:** для текущего уровня модели (22% recall) LM создаёт больше проблем, чем решает. Простой greedy/beam без LM работает лучше.

## Честное ограничение

Этот этап показал, что LM-конфиг **не работает** с расширенным корпусом. Это отрицательный результат, но он важен для понимания системы. Мы не скрываем его, а наоборот — подчёркиваем, что без LM лучше.
