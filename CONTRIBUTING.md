# Как помочь GestureLab

Спасибо за интерес к переводчику русского жестового языка. Проект находится в исследовательской стадии: улучшения должны измеряться на контрольных данных, а не оцениваться только по отдельным удачным примерам.

## Быстрый старт

1. Сделайте fork репозитория и клонируйте свою копию.
2. Установите Python 3.11 и создайте виртуальное окружение. На Windows путь к нему должен содержать только ASCII-символы — это требование текущей связки MediaPipe.
3. Установите зависимости:

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
python make_fixture.py
python -m pytest -q
```

4. Создайте отдельную ветку для изменения:

```bash
git switch -c fix/short-description
```

## Что особенно полезно

- улучшение извлечения и нормализации ландмарок;
- новые открытые данные РЖЯ с проверяемой лицензией и источником;
- разбиение train/test по видео и дикторам без утечки;
- выравнивание жестовых реплик и субтитров;
- CTC, temporal Transformer и другие модели непрерывного жестового языка;
- декодирование, языковые модели и перевод глосс в естественный русский;
- воспроизводимые бенчмарки и разбор ошибок;
- проверка с носителями РЖЯ и специалистами по жестовому языку.

## Правила изменений

- Один pull request — одна логически законченная идея.
- Для исправления ошибки сначала добавьте воспроизводящий тест, затем исправление.
- Не меняйте схему JSON-сессий молча: нужна новая версия, миграция и тест совместимости.
- Не добавляйте видео или фотографии реальных людей, личные записи, секреты, токены, большие датасеты и веса моделей. Используйте синтетические фикстуры и небольшие обезличенные результаты измерений.
- Указывайте источник и лицензию каждого нового внешнего ресурса. Лицензия MIT репозитория не меняет лицензии сторонних данных.
- Не сообщайте «точность» без набора данных, числа примеров, способа разбиения и использованной метрики. Для непрерывного РЖЯ отдельно указывайте word recall, WER/редакционное расстояние, exact phrase и долю пустых ответов, когда это применимо.

## Перед pull request

```bash
python -m pytest -q
git diff --check
```

Проверьте, что CI проходит. В описании pull request укажите:

1. какую проблему решает изменение;
2. что именно изменено;
3. какие команды и тесты запущены;
4. метрики до и после на одном и том же контрольном наборе;
5. известные ограничения и возможные регрессии.

## Обсуждения и ошибки

Используйте Issues для воспроизводимых ошибок и конкретных предложений, Discussions — для идей и вопросов. Для ошибки приложите версию Python и ОС, команду запуска, текст ошибки и минимальный пример без приватных данных.

Внося вклад, вы соглашаетесь с публикацией своего кода под лицензией MIT проекта.
